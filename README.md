# 昼中華3連単

火・水・木に店長が食べるお昼を当てる、社内向けの予想ゲームです。

- 画面：GitHub Pages（このリポジトリのファイル）
- データ：Google スプレッドシート ＋ Apps Script（`gas/Code.gs`）
- 写真：Google ドライブ

---

## はじめに準備すること（1回だけ・15分ほど）

### 1. スプレッドシートとApps Scriptを用意する

1. Google ドライブで **新しいスプレッドシート** を作り、名前を「昼中華3連単」にします。
2. メニューの **拡張機能 → Apps Script** を開きます。
3. 最初からある `コード.gs` の中身をすべて消し、このリポジトリの `gas/Code.gs` の中身を全部貼り付けて **保存**（💾）します。
4. 左の ⚙️ **プロジェクトの設定** → **タイムゾーン** を「(GMT+09:00) 日本標準時 - 東京」にします。
5. エディタに戻り、上の関数の選択欄で **`初期設定`** を選んで **▶ 実行** します。
   - 「承認が必要です」→ 自分のアカウントを選ぶ →「このアプリは Google で確認されていません」と出たら **詳細 → （安全ではないページ）に移動** → **許可**
   - スプレッドシートに「設定・参加者・週・メニュー・結果・予想・獲得pt・ログ」のシートができ、ドライブに「昼中華3連単の写真」フォルダができれば成功です。

### 2. Apps Scriptをウェブアプリとして公開する

1. 右上の **デプロイ → 新しいデプロイ**
2. 歯車 ⚙️ → **ウェブアプリ**
3. 次のように設定して **デプロイ**
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. 表示された **ウェブアプリの URL**（`https://script.google.com/macros/s/…/exec`）をコピーします。

### 3. GitHub に置く

1. GitHub で **New repository** → 名前 `hiru-chuka-sanrentan` → **Public** → **Create repository**
   - 無料プランの GitHub Pages は Public リポジトリが必要です。公開されるのは画面のプログラムだけで、予想やptなどのデータはスプレッドシートにあり、外からは見えません。
2. 手元でこのフォルダの `config.js` を開き、`API_URL: ''` の `''` の中に、手順2でコピーしたURLを貼って保存します。

   ```js
   window.CONFIG = {
     API_URL: 'https://script.google.com/macros/s/xxxxxxxx/exec',
   };
   ```
3. リポジトリの画面で **uploading an existing file** を押し、このフォルダの中身（`index.html`・`app.js`・`assets` フォルダなど全部）をドラッグして **Commit changes**。
4. **Settings → Pages** → Source を **Deploy from a branch**、Branch を **main / (root)** にして **Save**。
5. 数分後、`https://（あなたのGitHubユーザー名）.github.io/hiru-chuka-sanrentan/` で開けるようになります。このURLを参加者に伝えてください。

### 4. 自分をホストにする

1. アプリを開いて「はじめての方はこちら」から登録します。
2. スプレッドシートの **参加者** シートで、自分の行の **ホスト** にチェックを入れます。
3. アプリを開き直すと「ホスト」タブが出ます。ほかのホストも同じようにチェックで増やせます。

## 毎週の流れ

| いつ | だれ | やること |
|---|---|---|
| 月曜 | ホスト | ホストタブでメニューを人気の順に並べ、締切を決めて「出馬表を公開する」 |
| 火曜の締切まで | みんな | 予想タブで火・水・木を1つずつ選び、使うptを入れて決定（締切までは何度でも変更可） |
| 火〜木 | ホスト | 締切後、ホストタブでその日に食べたものを選び、写真を付けて「発表する」。メニュー外や休みの日は「中止にする」 |
| 木曜 | ホスト | 3日分そろったら「結果を確定する」→ ptが計算されて結果タブに出ます |

## ptのしくみ

- 最初の持ち点は全員 10,000pt（設定シートで変えられます）
- 日替わりpt：当たった日ごとに **使うpt × 1/3 × その品のオッズ**（端数切り捨て）
- 3連単：3日とも当たれば、さらに **使うpt × 3品のオッズのかけ算**
- 中止の日がある週は、使ったptを全額返します（当たり・はずれの記録だけ残ります）
- オッズは人気順で決まります（設定シートの「オッズ1〜8」「9番人気以降の増分」で調整できます）

## よくある作業

- **ptの補充**：持ち点が100pt未満になった人は、アプリの「ptを補充する」から自分で補充できます（豆知識クイズで＋5,000pt、レビューで＋15,000pt。額は設定シートの「クイズの補充pt」「レビューの補充pt」で変えられます）。補充の記録は「補充」シート、レビューの中身は「レビュー」シートに残ります（端末の種類などは記録しません）。手で足したいときは、これまでどおり参加者シートの「補充pt」に数を足します。
- **クイズの問題**：「クイズ」シートに入っています（最初に補充されたときに自動で100問が入ります）。問題を直したり足したりでき、「使う」のチェックを外すとその問題は出なくなります。
- **持ち点の計算**：初期持ち点 ＋ 補充pt ＋ これまでの獲得pt − これまでに使ったpt
- **問い合わせ**：参加者はアプリのメニュー「問い合わせ」から、種類（不具合・質問・要望・その他）と内容を送れます（ログインした人だけ・1人1時間に5件まで）。届いたものは「問い合わせ」シートに残り、エラー通知と同じ宛先にメールが届きます。返事の欄はないので、みんなに関係する内容は店長のつぶやき欄で知らせます。
- **パスワードを忘れた人**：参加者シートのその人の行を消すと、同じニックネームで登録し直せます（それまでの記録はなくなります）。
- **自動ログインの期限**：一度ログインした端末は自動でログインしますが、最後に使ってから30日あくと期限が切れ、もう一度ログインが必要になります（使うたびに延びます）。パスワードを変えると、変えた端末以外は自動ログインが切れます。ある人の自動ログインをすぐ止めたいときは、参加者シートのその人の「ログイン鍵」のセルを消します。
- **パスワードの回数ロック**：同じニックネームで続けて5回まちがえると、15分間ログインできなくなります（正しいパスワードでも不可・ほかの人には影響なし）。まちがいの回数は、最後のまちがいから15分たつか、ログインに成功すると0に戻ります。すぐ解除したいときは、Apps Script のエディタで関数「ログインロックを解除する」を実行します。ロックしたことは「ログ」シートに「ログインロック」として残ります。
- **Apps Script の更新（自動）**：GitHub の gas/Code.gs を更新すると、GitHub Actions（「Apps Script を更新」）が自動で Apps Script に反映し、新しいバージョンとしてデプロイします。URLは変わりません。結果はリポジトリの「Actions」タブで確認できます（緑のチェック＝成功、赤い×＝失敗）。
  - 必要な設定：リポジトリのシークレット `CLASPRC_JSON`（clasp login でできた ~/.clasprc.json の中身）と `SCRIPT_ID`（Apps Script のスクリプトID）。Apps Script API をオンにしておくこと
  - 失敗が続くとき：Googleのログインの期限切れが考えられます。Macで `clasp login` をやり直し、`pbcopy < ~/.clasprc.json` でコピーした中身で `CLASPRC_JSON` を更新します
  - 手で更新するとき：エディタに貼り付けて保存 → **デプロイ → デプロイを管理 → ✏️ 編集 → バージョン「新バージョン」→ デプロイ**

## バックアップ

毎週金曜の朝5時ごろ、スプレッドシートを丸ごとコピーして残します。

- **はじめに1回だけ**：Apps Script のエディタで関数「バックアップを設定する」を選んで ▶実行。許可を求められたら許可します。これで毎週の自動バックアップが始まり、1回目のバックアップもすぐ取られます。
- **保存先**：自分のGoogleドライブの「昼中華3連単のバックアップ」フォルダ。ファイル名は「昼中華3連単_バックアップ_日付_時刻」です。パスワードのハッシュも入っているので、**このフォルダは誰とも共有しないでください**。
- **残す数**：最新8回分（約2か月）。それより古いものはゴミ箱に移します（ゴミ箱から30日間は戻せます）。設定シートの「バックアップの保存数」で変えられます。
- **すぐ1回取りたいとき**（大きな変更の前など）：関数「バックアップを取る」を実行します。
- **戻すとき**：バックアップのファイルを開き、戻したいシートの中身（2行目以降）をコピーして、元のスプレッドシートの同じシートに貼り戻します。バックアップのファイルに乗り換えると、アプリのつながっている先が変わってしまうので、乗り換えはしないでください。写真はコピーされません（写真フォルダは消さないでください）。

## 本番の見張り

- 毎週金曜の朝7時ごろ、GitHub Actions（「本番の見張り」）が本番に問い合わせて、本番のURLが返事をするか、今朝のバックアップがあるか、毎週のバックアップの予約が残っているかを確かめます。
- おかしければ失敗になり、GitHub からメールが届きます（GitHub の Settings → Notifications の「Actions」で、失敗時にメールが届く設定にしておく）。
- Apps Script のメールや予約そのものが止まっていても、外から見ているので気づけます。手で実行するときは「Actions」タブ →「本番の見張り」→「Run workflow」（このときは1週間以内のバックアップがあれば OK）。

## エラーの通知

- サーバーで想定外のエラーが起きると、スプレッドシートの「エラー」シートに記録し、オーナーにメールで知らせます（メールは1時間に1通まで。その間のエラーは次のメールに件数が書かれます）。
- 画面（ブラウザ）で起きたエラーも、サーバーに送られて「エラー」シートに記録されます（1回の表示で3件まで、全体で10分に30件まで）。
- 宛先を変えたいときは、設定シートの「エラー通知先」にメールアドレスを書きます（空ならオーナー）。
- **はじめに1回だけ**：Apps Script のエディタで関数「エラー通知のテスト」を実行して、メール送信を許可します。テストのメールが届き、「エラー」シートにテストの行ができれば準備完了です（「エラー」シートは最初のエラーが起きたときに自動でできます）。

## テスト環境

本番とは別に、試すための環境があります。テスト環境で何をしても本番のデータには影響しません。

| | 本番 | テスト環境 |
|---|---|---|
| 画面 | https://tansan88.github.io/hiru-chuka-sanrentan/ | https://tansan88.github.io/hiru-chuka-sanrentan/test/ （左下に赤い「テスト環境」の印） |
| データ | スプレッドシート「昼中華3連単」 | スプレッドシート「昼中華3連単（テスト）」 |
| 反映されるブランチ | main | test |

- **流れ**：変更はまず `test` ブランチに入れる → テスト環境に自動で反映 → 試して問題なければ `main` に入れる → 本番に自動で反映。
- **本番に入れてよいかの判断（OK を出す人）**：オーナー（Shota）。
  1. Claude が自動テストと模擬環境での確認を済ませてから `test` に入れる（テスト環境に反映されると、テスト用アカウント「ci〜」で登録〜画面の読み込みまで自動で試す）
  2. Claude が「何を変えたか」と「テスト環境で触って確かめてほしいこと」を2〜3点にまとめて伝える
  3. オーナーがテスト環境で確かめて OK を出したら、Claude が `main` に入れる
  4. 例外：本番が止まっているなど急ぎの修正は、先に一言伝えてから本番に直接入れ、あとで `test` にもそろえる
- テスト環境の参加者シートには、自動の通し確認で作ったアカウント（ニックネームが「ci」で始まる）がたまっていきます。消してかまいません。
- 本番の画面のURLに `?env=test` を付けると、本番の画面のままテスト環境のサーバーにつながります（古い画面と新しいサーバーの組み合わせを試すとき用）。
- ログインは本番とテスト環境で別々に覚えます。テスト環境から届くメールの件名には「［テスト環境］」が付き、テスト環境で作るフォルダの名前には「（テスト）」が付きます。
- 画面の公開は GitHub Actions（「画面を公開」）で行います。リポジトリの Settings → Pages の Source は「GitHub Actions」にしておきます。

## 画面の版のずれ

- 画面（app.js の `APP_VERSION`）は、操作のたびに自分の版をサーバーに送ります。
- サーバー（gas/Code.gs の `MIN_APP_VERSION`）より古い画面から操作が来ると、画面に「アプリが新しくなりました」と出て、開き直してもらいます。選んでいた予想は開き直しても残ります。
- 古い画面からの送り方と食い違う変更をしたときだけ、`APP_VERSION` と `MIN_APP_VERSION` を同じ数に上げます。ふだんは上げません。

## テスト

- `node test/run.js` で、サーバー（gas/Code.gs）のテストをまとめて実行できます（Node.js だけで動き、追加のインストールは不要）。
- Apps Script のかわりに、手元で動く模擬サーバー（test/emu）を使います。スプレッドシートの型変換（数字・日付・数式）も本物に近く真似ています。
- GitHub に反映すると自動でテストが走り、通ったときだけ Apps Script が更新されます。

## 注意

- スプレッドシートの持ち主（オーナー）は、全員の予想を見られます。
- 写真はドライブの「昼中華3連単の写真」フォルダに入り、リンクを知っている人が見られる設定になります。
- シェアボタンを押すと、結果の画像がコピーされます。スマホやSlackのバージョンによって貼り付けられない場合は「画像を保存」してから投稿してください。

## ホストの便利機能
- **スクショから出馬表**：ホストタブの「エアレジのスクショから読み込む」で、画像の中の「1.」〜「5.」で始まるメニュー名を1〜5番に入れます。Google ドライブの文字認識を使うため、Apps Script の「Drive API」（詳細サービス）を使います（GitHub から反映するときに自動で有効にします）。読み取りに使ったファイルはすぐゴミ箱に入れます。
- **いつものメニュー**：ホストタブの「いつものメニュー」に入れた2品が、新しい週の6・7番に自動で入ります（設定シートの「いつものメニュー1・2」）。8番には「その他」が入り、結果を登録するときに実際の料理名を入れます。
- **食べたものの登録**：メニューをタップするとカメラが開きます。発表したあと「Slackに送る」で、写真と「メニュー名 :hirucyuuka:」を共有の画面から Slack へ送れます（送り先は Slack の画面で選ぶ。文字はコピーもされます）。アプリに保存するのは写真だけです。
- **投稿をつくる**：`?post` を付けて開く（メニューの「Slackへの投稿をつくる」）と、三連単と関係なく、写真＋メニュー名を Slack へ送るだけの画面になります。ログイン不要で、何も記録しません。ホーム画面に追加しておくと便利です。
- **テスト環境だけ**：公開中の週に「締切を今にする」ボタンが出て、曜日や締切を待たずに食べたものの登録と結果を試せます（本番では使えません）。
